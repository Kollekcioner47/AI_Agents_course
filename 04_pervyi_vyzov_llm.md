# Занятие 4. Первый вызов модели: ассистент отвечает в консоли.

До этого занятия ассистент был просто набором файлов, которые печатают
на экран то, что в них написано. Сегодня у него появляется мозг: вы
напишете программу, которая отправляет ваш вопрос языковой модели и
возвращает её ответ. Впервые ассистент ответит не заученной строкой,
а осмысленным текстом, который модель придумала в момент запроса.

Занятие короткое по коду, но важное по смыслу. Вы поймёте, как
программа общается с моделью по интернету, куда класть секретный ключ
и как из длинного ответа сервера достать ровно тот текст, который нужен
человеку. После занятия у ассистента будет первый рабочий «мозг».

## ЧТО МЫ СДЕЛАЕМ

Напишем три файла, которые вместе дают ассистенту голос: config.py
с настройками провайдеров, llm.py с единственной функцией chat() и
chat.py с циклом «вопрос → ответ». По дороге получим API-ключ NeuralDeep
или поставим локальную модель Ollama и спрячем ключ в файл .env,
чтобы он никогда не попал в код.

После занятия вы сможете объяснить, что такое API и HTTP-запрос,
зачем нужен файл .env и почему у NeuralDeep и Ollama одинаковый адрес
/chat/completions.

## ЧАСТЬ 1. ТЕОРИЯ: КАК АССИСТЕНТ ГОВОРИТ С МОДЕЛЬЮ

### ШАГ 1. ЧТО ТАКОЕ API И HTTP-ЗАПРОС

Языковая модель не «живёт» в вашем компьютере. Это программа, которая
работает на сервере компании (или на вашем же компьютере, если вы
поставили Ollama). Чтобы попросить её ответить, наша программа должна
послать ей сообщение по интернету и дождаться ответа. Такой способ
общения называется API — «интерфейс программирования приложений».

Проще говоря: API — это дверь, через которую одна программа просит
другую что-то сделать. Такой запрос по интернету называется
HTTP-запросом и состоит из трёх частей:

  * АДРЕС (URL) — куда стучимся, например https://api.neuraldeep.ru/v1;
  * ТЕЛО (body) — что просим сделать, то есть наш вопрос;
  * ЗАГОЛОВКИ (headers) — служебная информация, в том числе ключ.

Всё это в нашем коде делает одна строка requests.post(...) — о ней
в шаге 4.

### ШАГ 2. JSON И ОДИН АДРЕС /CHAT/COMPLETIONS

Запрос и ответ передаются в формате JSON — это текст, где данные
записаны в фигурных скобках как пары «имя: значение»:

```python
{"role": "user", "content": "Привет!"}
```

Здесь role — кто говорит (user — вы), content — сам текст сообщения.

У NeuralDeep и Ollama есть общая черта: обе понимают «OpenAI-совместимый»
формат запроса. Это значит, что сообщение нужно отправлять на один и
тот же адрес, который заканчивается на /chat/completions:

```python
https://api.neuraldeep.ru/v1/chat/completions
http://127.0.0.1:11434/v1/chat/completions
```

Первый адрес — сервер NeuralDeep в интернете, второй — локальная Ollama.
Адрес сервера называют base_url, а последнюю часть /chat/completions —
endpoint (точка входа). ЗАПОМНИТЕ: base_url у провайдеров разный,
а endpoint одинаковый. Поэтому один и тот же код умеет говорить и
с NeuralDeep, и с Ollama — достаточно подменить base_url и имя модели.
Именно так устроен наш config.py.

### ШАГ 3. API-КЛЮЧ И ФАЙЛ .ENV

Сервер NeuralDeep не отвечает первому встречному: нужно доказать, что
вы — это вы. Для этого вы получаете длинную строку-пароль — API-ключ —
и отправляете её с каждым запросом в заголовке Authorization. Так
сервер понимает, на чей счёт записать вызов.

Куда положить ключ? Только в файл .env, а не в код:

  * ключ — это пароль от вашего счёта. Если он попадёт в файл с кодом,
  который вы покажете или выложите, — его украдут и будут тратить
  ваш баланс;
  * .env — обычный текстовый файл с настройками, по одной строке
  КЛЮЧ=ЗНАЧЕНИЕ. Программа читает его при запуске и подставляет
  значения в переменные окружения;
  * .env заносят в список .gitignore, чтобы система контроля версий
  (Git) никогда его не публиковала. Даже без Git привычка правильная.

ОСТОРОЖНО: ключ хранится только в файле .env. Никому его не показывайте,
не вставляйте в файл с кодом и не отправляйте в чат с самой моделью.
Если ключ случайно «засветился» — перевыпустите его в личном кабинете:
пароль, который утёк, лечится только заменой.

### ШАГ 4. МИНИМАЛЬНЫЙ ЗАПРОС REQUESTS.POST

Библиотека requests умеет отправлять HTTP-запросы одной строкой. Для
вызова модели нужен запрос типа POST — «положи серверу вот это тело
и верни результат». В минимальном виде он выглядит так:

```python
import requests

url = "https://api.neuraldeep.ru/v1/chat/completions"
payload = {"model": "qwen3.8-27b", "messages": [{"role": "user", "content": "Привет!"}]}
headers = {"Authorization": "Bearer sk-..."}
r = requests.post(url, json=payload, headers=headers, timeout=120)
```

Разберём по частям:

  * url — полный адрес: base_url + "/chat/completions";
  * payload — тело запроса: модель (model) и список сообщений (messages);
  * headers — заголовок Authorization со словом Bearer и ключом
  (Bearer — договорённость «передаю ключ доступа»);
  * json=payload — requests сам превратит словарь в текст JSON;
  * timeout=120 — сколько секунд ждать ответа.

Сервер вернёт объект r, внутри которого текст ответа и служебная
информация. Как достать сам ответ — в шаге 5.

### ШАГ 5. РАЗБОР ОТВЕТА CHOICES[0].MESSAGE.CONTENT

Ответ сервера — это большой JSON с массой служебных полей: сколько
токенов потрачено, как долго отвечала модель и так далее. Нас
интересует только сам текст. Он лежит по такому пути:

```python
r.json()["choices"][0]["message"]["content"]
```

Читаем путь слева направо:

  * r.json() — превращаем ответ из текста JSON в словарь Python;
  * ["choices"] — список вариантов ответа, берём первый;
  * [0] — первый (и обычно единственный) вариант;
  * ["message"]["content"] — внутри варианта лежит сообщение, а в нём —
  поле content, то есть сам текст, который модель написала.

Всё остальное в ответе нам пока не нужно. Поэтому функция chat() в
llm.py делает три вещи: отправляет запрос, проверяет, что сервер не
вернул ошибку (raise_for_status), и возвращает только текст из
choices[0].message.content.

### ДЕМО 3. НАПИСАТЬ CONFIG.PY И LLM.PY

Преподаватель создаёт config.py — настройки и маленький загрузчик .env:

```python
import os

def load_env(path=".env"):
    """Читает файл .env построчно и подставляет переменные окружения."""
    try:
        with open(path, "r", encoding="utf-8") as f:
            for line in f:
                line = line.strip()
                if not line or line.startswith("#") or "=" not in line:
                    continue
                key, value = line.split("=", 1)
                os.environ.setdefault(key.strip(), value.strip())
    except FileNotFoundError:
        pass

load_env()

PROVIDERS = {
    "neuraldeep": {
        "base_url": os.environ.get("NEURALDEEP_BASE_URL", "https://api.neuraldeep.ru/v1"),
        "api_key": os.environ.get("NEURALDEEP_API_KEY", ""),
        "model": os.environ.get("NEURALDEEP_MODEL", "qwen3.8-27b"),
    },
    "ollama": {
        "base_url": os.environ.get("OLLAMA_BASE_URL", "http://127.0.0.1:11434/v1"),
        "api_key": "",
        "model": os.environ.get("OLLAMA_MODEL", "qwen3:8b"),
    },
}

DEFAULT_PROVIDER = "neuraldeep" if PROVIDERS["neuraldeep"]["api_key"] else "ollama"
```

Ключевая строка — DEFAULT_PROVIDER: если в .env есть ключ NeuralDeep,
работаем с NeuralDeep, если ключа нет — берём локальную Ollama.

Затем преподаватель создаёт llm.py с функцией chat():

```python
import requests

from config import DEFAULT_PROVIDER, PROVIDERS

def chat(messages, provider=None):
    provider = provider or DEFAULT_PROVIDER
    cfg = PROVIDERS[provider]
    url = cfg["base_url"].rstrip("/") + "/chat/completions"
    payload = {"model": cfg["model"], "messages": messages}
    headers = {"Authorization": "Bearer " + cfg["api_key"]} if cfg["api_key"] else {}
    r = requests.post(url, json=payload, headers=headers, timeout=120)
    r.raise_for_status()
    return r.json()["choices"][0]["message"]["content"]
```

Он обращает внимание: provider=None значит «возьми провайдера по
умолчанию», rstrip("/") убирает лишний слэш в конце base_url, а
raise_for_status() бросает понятную ошибку, если сервер ответил
неудачей.

## ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК

### ПРОБЛЕМА: «401 Unauthorized» при запуске

Сервер не принял ваш ключ. Причины: ключ пустой (строка
NEURALDEEP_API_KEY= без значения), ключ перепутан или в нём лишние
пробелы. Проверьте .env: ключ должен идти сразу после «=», без кавычек
и пробелов. Не помогло — перевыпустите ключ в личном кабинете.

### ПРОБЛЕМА: «Connection error» или «Failed to establish a new connection»

Программа не смогла достучаться до сервера. Для NeuralDeep проверьте
интернет и то, что base_url записан без опечаток. Для Ollama проверьте,
что программа запущена (ollama serve или значок в трее) и что адрес
http://127.0.0.1:11434/v1 верный.

### ПРОБЛЕМА: «model not found» или похожее сообщение о модели

Сервер не знает такую модель. Сверьте имя в .env с точным названием:
у NeuralDeep это qwen3.8-27b, у Ollama — ровно то имя, которое вы
скачивали командой ollama pull (например, qwen3:8b). Лишний пробел
или неверная буква — и модель «не находится».

### ПРОБЛЕМА: «ModuleNotFoundError: No module named 'requests'»

Библиотека requests не установлена. Выполните в терминале:

```python
pip install requests
```

и запустите программу снова.

### ПРОБЛЕМА: программа не видит ключ, хотя .env заполнен

Файл .env лежит не в той папке или называется иначе (например, env.txt
или .env.txt). Он должен лежать рядом с config.py и называться ровно
.env. Проверьте формат: одна строка — одна пара КЛЮЧ=ЗНАЧЕНИЕ, без
кавычек, а комментарии начинаются с символа #.
