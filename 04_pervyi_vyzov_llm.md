## ЧАСТЬ 1. ТЕОРИЯ: КАК АССИСТЕНТ ГОВОРИТ С МОДЕЛЬЮ

### ШАГ 1. ЧТО ТАКОЕ ЗАПРОС К МОДЕЛИ

Языковая модель — это программа, которая работает на сервере (или на
вашем же компьютере, если вы поставили Ollama). Чтобы получить от неё
ответ, наша программа отправляет ей сообщение по интернету и ждёт
ответа. Такой обмен «вопрос → ответ» называется запросом к модели, а
способ, которым программы общаются между собой, — API, «интерфейс
программирования приложений».

Проще говоря: API — это дверь, через которую одна программа просит
другую что-то сделать. Чтобы попросить модель ответить, программе
нужны всего три вещи:

  * АДРЕС — куда отправлять запрос. Его называют base_url;
  * ТЕКСТ ВОПРОСА — что мы хотим спросить;
  * КЛЮЧ — для NeuralDeep: строка, которая доказывает, что это вы
  (о ней в шаге 2).

Весь запрос в нашем коде делает одна строка requests.post(...).
Как именно она устроена внутри, для первого занятия знать не
обязательно: важно, что она отправляет вопрос и возвращает ответ.

### ШАГ 2. ЧТО ТАКОЕ API-КЛЮЧ И ФАЙЛ .ENV

Сервер NeuralDeep отвечает не каждому: нужно доказать, что вы — это
вы. Для этого вы получаете длинную строку-пароль — API-ключ — и
отправляете её с каждым запросом. По ключу сервер понимает, на чей
счёт записать вызов.

Куда положить ключ? Только в файл .env, а не в код:

  * ключ — это пароль от вашего счёта. Если он попадёт в файл с кодом,
  который вы покажете или выложите, — его украдут и будут тратить
  ваш баланс;
  * .env — обычный текстовый файл с настройками, по одной строке
  КЛЮЧ=ЗНАЧЕНИЕ. Программа читает его при запуске и подставляет
  значения в переменные окружения;
  * .env заносят в список .gitignore, чтобы система контроля версий
  (Git) никогда его не публиковала. Даже без Git привычка правильная.

ОСТОРОЖНО: ключ хранится только в файле .env. Никому его не показывайте,
не вставляйте в файл с кодом и не отправляйте в чат с самой моделью.
Если ключ случайно «засветился» — перевыпустите его в личном кабинете:
пароль, который утёк, лечится только заменой.

### ШАГ 3. ОДИН АДРЕС ДЛЯ ДВУХ ПРОВАЙДЕРОВ

У NeuralDeep и Ollama разные адреса сервера (base_url):

```python
https://api.neuraldeep.ru/v1
http://127.0.0.1:11434/v1
```

Первый — сервер NeuralDeep в интернете, второй — локальная Ollama на
вашем компьютере. Но последняя часть адреса у них одинаковая:
/chat/completions. Значит, обе модели понимают один и тот же формат
запроса. Поэтому один и тот же код умеет говорить и с NeuralDeep, и
с Ollama — достаточно подменить base_url и имя модели. Именно так
устроен наш config.py.

```python
import os
import requests

# ЧТО: читаем .env построчно и делаем каждую пару ИМЯ=ЗНАЧЕНИЕ переменной окружения.
# ЗАЧЕМ: так скрипт узнаёт адрес, модель и ключ, не зашивая их в код.
for line in open(".env", encoding="utf-8"):
    if "=" in line:
        name, value = line.strip().split("=", 1)
        os.environ[name] = value

# ЧТО: выбираем провайдера. ПОЧЕМУ так: есть ключ NeuralDeep — облако, нет — локальная Ollama.
if os.environ.get("NEURALDEEP_API_KEY"):
    base_url, model, key = os.environ["NEURALDEEP_BASE_URL"], os.environ["NEURALDEEP_MODEL"], os.environ["NEURALDEEP_API_KEY"]
else:
    base_url, model, key = os.environ["OLLAMA_BASE_URL"], os.environ["OLLAMA_MODEL"], ""

# ЧТО: собираем адрес, тело запроса и заголовок с ключом. ЗАЧЕМ: серверу нужно, куда и что слать.
url = base_url + "/chat/completions"
body = {"model": model, "messages": [{"role": "user", "content": "Привет!"}]}
headers = {"Authorization": "Bearer " + key} if key else {}

# ЧТО: отправляем запрос и ждём ответ. ПОЧЕМУ json=body: requests сам превратит словарь в текст JSON.
r = requests.post(url, json=body, headers=headers, timeout=120)

# ЧТО: достаём из ответа сам текст и печатаем его — это и есть ответ модели.
print(r.json()["choices"][0]["message"]["content"])
```

### ПРИМЕР 4. ВЫНЕСТИ ВЫЗОВ В CONFIG.PY И LLM.PY

Сейчас запрос к модели зашит прямо в hello_model.py. Если понадобится
спросить модель ещё раз или сменить провайдера, придётся повторять
одни и те же строки. Вынесем настройки и вызов в два файла.

Создайте config.py — настройки провайдеров и маленький загрузчик .env:

```python
import os

# ЧТО: читаем .env построчно и подставляем значения в переменные окружения.
# ПОЧЕМУ setdefault: не перезаписывает уже заданное и не падает, если .env нет.
def load_env(path=".env"):
    try:
        with open(path, "r", encoding="utf-8") as f:
            for line in f:
                line = line.strip()
                # ЗАЧЕМ: пропускаем пустые строки и комментарии.
                if not line or line.startswith("#") or "=" not in line:
                    continue
                key, value = line.split("=", 1)
                os.environ.setdefault(key.strip(), value.strip())
    except FileNotFoundError:
        pass

load_env()

# ЧТО: настройки обоих провайдеров в одном словаре.
# ЗАЧЕМ: смена провайдера — это одна строка, а не правка кода.
PROVIDERS = {
    "neuraldeep": {
        "base_url": os.environ.get("NEURALDEEP_BASE_URL", "https://api.neuraldeep.ru/v1"),
        "api_key": os.environ.get("NEURALDEEP_API_KEY", ""),
        "model": os.environ.get("NEURALDEEP_MODEL", "qwen3.8-27b"),
    },
    "ollama": {
        "base_url": os.environ.get("OLLAMA_BASE_URL", "http://127.0.0.1:11434/v1"),
        "api_key": "",
        "model": os.environ.get("OLLAMA_MODEL", "qwen3:8b"),
    },
}

# ЧТО: провайдер по умолчанию. ПОЧЕМУ так: есть ключ NeuralDeep — облако, нет — Ollama.
DEFAULT_PROVIDER = "neuraldeep" if PROVIDERS["neuraldeep"]["api_key"] else "ollama"
```

Ключевая строка — DEFAULT_PROVIDER: если в .env есть ключ NeuralDeep,
работаем с NeuralDeep, если ключа нет — берём локальную Ollama.

Создайте llm.py с функцией chat():

```python
import requests

from config import DEFAULT_PROVIDER, PROVIDERS

# ЧТО: одна функция отправляет сообщения модели и возвращает только текст ответа.
# ЗАЧЕМ: вызов больше не повторяется в каждом скрипте.
def chat(messages, provider=None):
    provider = provider or DEFAULT_PROVIDER  # ПОЧЕМУ: None — «возьми провайдера по умолчанию».
    cfg = PROVIDERS[provider]
    url = cfg["base_url"].rstrip("/") + "/chat/completions"  # rstrip убирает лишний слэш в base_url.
    payload = {"model": cfg["model"], "messages": messages}
    headers = {"Authorization": "Bearer " + cfg["api_key"]} if cfg["api_key"] else {}
    r = requests.post(url, json=payload, headers=headers, timeout=120)
    r.raise_for_status()  # ЧТО: бросает понятную ошибку, если сервер ответил неудачей.
    return r.json()["choices"][0]["message"]["content"]
```

Обратите внимание: provider=None значит «возьми провайдера по
умолчанию», rstrip("/") убирает лишний слэш в конце base_url, а
raise_for_status() бросает понятную ошибку, если сервер ответил
неудачей.

СДЕЛАНО, ЕСЛИ: config.py и llm.py созданы, и вы можете объяснить,
зачем понадобилась функция chat() (чтобы не повторять запрос каждый
раз заново).

### ПРИМЕР 5. ЦИКЛ ОБЩЕНИЯ CHAT.PY

Осталось обернуть вызов в цикл, чтобы не перезапускать программу ради
каждого вопроса. Создайте chat.py:

```python
from llm import chat

# ЧТО: печатаем подсказку, как выйти из программы.
print("Ассистент готов. Пустая строка — выход.")

# ЧТО: бесконечный цикл «вопрос → ответ». ЗАЧЕМ: не перезапускать программу на каждый вопрос.
while True:
    text = input("> ")
    if text.strip() == "":  # ЗАЧЕМ: пустая строка — выход из цикла.
        break
    answer = chat([{"role": "user", "content": text}])  # ЗАЧЕМ: передаём вопрос модели одним сообщением.
    print(answer)
```

Запустите:

```python
python chat.py
```

ассистент отвечает осмысленной фразой, например:

СДЕЛАНО, ЕСЛИ: chat.py отвечает на несколько вопросов подряд, и вы

## ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК

### ПРОБЛЕМА: «401 Unauthorized» при запуске

Сервер не принял ваш ключ. Причины: ключ пустой (строка
NEURALDEEP_API_KEY= без значения), ключ перепутан или в нём лишние
пробелы. Проверьте .env: ключ должен идти сразу после «=», без кавычек
и пробелов. Не помогло — перевыпустите ключ в личном кабинете.

### ПРОБЛЕМА: «Connection error» или «Failed to establish a new connection»

Программа не смогла достучаться до сервера. Для NeuralDeep проверьте
интернет и то, что base_url записан без опечаток. Для Ollama проверьте,
что программа запущена (ollama serve или значок в трее) и что адрес
http://127.0.0.1:11434/v1 верный.

### ПРОБЛЕМА: «model not found» или похожее сообщение о модели

Сервер не знает такую модель. Сверьте имя в .env с точным названием:
у NeuralDeep это qwen3.8-27b, у Ollama — ровно то имя, которое вы
скачивали командой ollama pull (например, qwen3:8b). Лишний пробел
или неверная буква — и модель «не находится».

### ПРОБЛЕМА: «ModuleNotFoundError: No module named 'requests'»

Библиотека requests не установлена. Выполните в терминале:

```python
pip install requests
```

и запустите программу снова.

### ПРОБЛЕМА: программа не видит ключ, хотя .env заполнен

Файл .env лежит не в той папке или называется иначе (например, env.txt
или .env.txt). Он должен лежать рядом с config.py и называться ровно
.env. Проверьте формат: одна строка — одна пара КЛЮЧ=ЗНАЧЕНИЕ, без
кавычек, а комментарии начинаются с символа #.
