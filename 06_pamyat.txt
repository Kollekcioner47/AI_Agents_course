Занятие 6. Память: ассистент запоминает факты и заметки.

Ася умеет отвечать в консоли и держит характер, но между запусками
программы всё забывает: вчера вы сказали, как вас зовут, а сегодня
она снова спрашивает. На этом занятии даём ассистенту память — место,
куда он записывает факты о вас и заметки и откуда читает их назад.
Ассистента зовут Ася, пользователя в примерах — Алексей.

Память — третий блок ассистента после мозга и характера. Собирается
она из базы SQLite для коротких фактов («имя = Алексей») и папки
с заметками markdown для длинных текстов. И то и другое — файлы на
диске, поэтому переживает перезапуск.

========================================================================
ЧТО МЫ СДЕЛАЕМ
========================================================================

Создадим базу SQLite и таблицу profiles, напишем функции, которые
кладут факт в базу и читают его назад, научимся сохранять длинные
заметки в markdown и подключим всё к диалогу: «запомни …» записывает
факт, «что ты помнишь» — перечисляет всё, что знает Ася. После
занятия она будет помнить вас между запусками: факт «имя = Алексей»
лежит в файле базы, а не в голове модели.

ЧАСТЬ 1. ТЕОРИЯ: ЗАЧЕМ АССИСТЕНТУ ПАМЯТЬ И КАК ОНА УСТРОЕНА

========================================================================
ШАГ 1. ПОЧЕМУ МОДЕЛЬ НИЧЕГО НЕ ПОМНИТ
========================================================================

Языковая модель — это функция: текст на входе, текст на выходе. Между
двумя вызовами у неё нет состояния: каждый запрос — вычисление с нуля.
Если в сообщении не было вашего имени, модель не может его знать —
ей неоткуда его взять. Историю внутри беседы хранит программист:
он держит сообщения и каждый раз заново отправляет их модели.

ЗАПОМНИТЕ: память ассистента строит программист, а не модель. Нужно
место на диске для фактов и код, который перед ответом их оттуда
читает.

========================================================================
ШАГ 2. SQLITE: БАЗА = ФАЙЛ, ТАБЛИЦЫ, СТРОКИ
========================================================================

База данных — это файл на диске, например assistant.db. Внутри лежат
таблицы: прямоугольники из колонок и строк. Колонки задают поля,
строки — конкретные записи. Наша таблица profiles имеет три колонки:

    section | key  | value
    --------+------+---------
    факты   | имя  | Алексей

section — раздел, key — ключ, value — значение. Одна строка — один
факт. Аналогия: база — шкаф, таблица — ящик с карточками, строка —
карточка.

Пара (section, key) уникальна: двух строк «факты» + «имя» быть
не может, поэтому повторная запись обновляет старую, а не плодит
дубликаты — увидим в шаге 4.

========================================================================
ШАГ 3. БАЗОВЫЙ SQL: CREATE TABLE / INSERT / SELECT / UPDATE
========================================================================

SQL — язык запросов к базе. Нужны четыре команды.

CREATE TABLE — создать таблицу (выполняется один раз):

    CREATE TABLE IF NOT EXISTS profiles (
        section TEXT,
        key TEXT,
        value TEXT,
        PRIMARY KEY(section, key)
    )

Читается так: «создай таблицу profiles, если её нет, с тремя текстовыми
колонками; пара (section, key) не повторяется». IF NOT EXISTS — «если
уже есть, ничего не делай».

INSERT — добавить строку:

    INSERT INTO profiles(section, key, value) VALUES('факты', 'имя', 'Алексей')

SELECT — прочитать строки:

    SELECT value FROM profiles WHERE section='факты' AND key='имя'

UPDATE — изменить существующую строку:

    UPDATE profiles SET value='Алексей' WHERE section='факты' AND key='имя'

ОСТОРОЖНО: значения в запрос не вклеивают как текст. Вместо 'факты',
'имя' ставят заглушки «?», а значения Python передаёт отдельно:

    INSERT INTO profiles(section, key, value) VALUES(?, ?, ?)

Заглушки защищают от опечаток с кавычками и порчи базы чужим текстом:
данные от пользователя идут только через «?».

========================================================================
ШАГ 4. memory.py: SET И GET ПРОФИЛЯ
========================================================================

В db.py — подключение к базе и создание таблицы:

    import sqlite3

    def connect(path):
        con = sqlite3.connect(str(path))
        con.execute("""CREATE TABLE IF NOT EXISTS profiles (section TEXT, key TEXT, value TEXT, PRIMARY KEY(section,key))""")
        return con

В memory.py — запись и чтение факта:

    def set_profile(con, section, key, value):
        con.execute("INSERT INTO profiles(section,key,value) VALUES(?,?,?) ON CONFLICT(section,key) DO UPDATE SET value=excluded.value", (section, key, str(value)))
        con.commit()

    def get_profile(con, section, key):
        row = con.execute("SELECT value FROM profiles WHERE section=? AND key=?", (section, key)).fetchone()
        return row[0] if row else None

ON CONFLICT(section,key) DO UPDATE означает: если пара «раздел + ключ»
уже есть, не создавай вторую строку, а обнови значение у старой. Одна
команда и добавляет, и исправляет — «upsert». con.commit() пишет
изменение в файл базы: без него INSERT пропадает при закрытии
программы. get_profile возвращает row[0], если строка есть, и None,
если её нет.

========================================================================
ШАГ 5. ЗАМЕТКИ В MARKDOWN (VAULT)
========================================================================

База удобна для коротких фактов, но длинный текст — план отпуска,
список покупок — в таблицу неудобен. Такие тексты храним файлами.
Markdown — обычный текст с простой разметкой: «#» — заголовок, «-» —
пункт списка, **звёздочки** — жирный. Пример: files/06_pamyat/
primer_zametka.md.

Заметки складываем в папку vault, по одному файлу на заметку:

    import pathlib

    VAULT = pathlib.Path("vault")

    def write_note(section, key, content):
        VAULT.mkdir(exist_ok=True)
        path = VAULT / f"{section}__{key}.md"
        path.write_text(content, encoding="utf-8")
        return path

    def read_note(section, key):
        path = VAULT / f"{section}__{key}.md"
        if not path.exists():
            return None
        return path.read_text(encoding="utf-8")

write_note создаёт папку vault, если её нет, и кладёт текст в файл;
read_note читает файл или возвращает None. encoding="utf-8" фиксирует
кодировку. Раздел и ключ для заметки берите латиницей («plany»,
«otpusk»): из них получается имя файла.

========================================================================
ШАГ 6. КАК ПОДКЛЮЧИТЬ ПАМЯТЬ К ДИАЛОГУ
========================================================================

В chat.py перед вызовом модели проверяем две команды:

    import db
    import memory

    con = db.connect("assistant.db")

    while True:
        message = input("Вы: ")
        if message == "":
            break
        if message.startswith("запомни "):
            rest = message[len("запомни "):]
            key, value = rest.split(":", 1)
            memory.set_profile(con, "факты", key.strip(), value.strip())
            print("Ася: запомнила «" + key.strip() + "».")
            continue
        if message == "что ты помнишь":
            rows = con.execute("SELECT section, key, value FROM profiles ORDER BY section, key").fetchall()
            if not rows:
                print("Ася: пока ничего не помню.")
            else:
                for section, key, value in rows:
                    print("Ася: [" + section + "] " + key + " = " + value)
            continue
        # ... дальше код вызова модели из занятий 4–5 ...

«запомни …»: отрезаем слово, остаток режем по первому двоеточию на
ключ и значение и сохраняем в раздел «факты». «что ты помнишь»:
читаем все строки и печатаем. Факты лежат в файле assistant.db:
перезапустите программу — connect откроет тот же файл, и «что ты
помнишь» всё ещё покажет имя = Алексей.

ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК
========================================================================

ПРОБЛЕМА: «no such table: profiles»

Выполняете SQL до того, как создали таблицу. Чаще всего connect() не
вызван, либо в запросе другое имя таблицы. Проверьте: перед любым
INSERT или SELECT вызывается db.connect(), а имя таблицы везде одно —
profiles.

ПРОБЛЕМА: «database is locked»

Файл базы занят другим процессом: открыта вторая копия программы или
старый процесс не завершился. Закройте лишние терминалы, оставьте
одно подключение на программу и перезапустите.

ПРОБЛЕМА: операции не сохраняются

Забыли con.commit(). Пока программа работает, INSERT виден внутри неё,
но после закрытия изменения исчезают. Добавьте con.commit() сразу
после каждого INSERT или UPDATE.

ПРОБЛЕМА: не видит данные между запусками

Программа в разных запусках открывает разные файлы. Так бывает, если
запускать из разных папок: путь «assistant.db» указывает в разные
места. Запускайте всегда из папки проекта и используйте одно имя
файла.

ПРОБЛЕМА: «UnicodeDecodeError» при чтении заметки

Файл сохранён не в UTF-8. В write_note и read_note должно стоять
encoding="utf-8". Если заметку записали раньше в другой кодировке,
пересохраните её как UTF-8 или запишите заново.
