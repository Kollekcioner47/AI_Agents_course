Занятие 7. Инструменты: ассистент вызывает функции.

До этого занятия ассистент умел говорить: отвечал, помнил факты, держал
характер. Но языковая модель лишь предсказывает текст — она не знает,
который час, не заглянет в файл и не сложит честно два числа, а просто
звучит убедительно.

Сегодня ассистент перестаёт быть болтуном: вы даёте ему инструменты —
функции, которые он вызывает сам, когда нужны точные данные. Ася
впервые делает что-то, а не только пишет.

========================================================================
ЧТО ВЫ СДЕЛАЕТЕ
========================================================================

Научите ассистента вызывать функции через механизм function calling.
Напишете инструмент «текущее время», опишете его схемой для модели
и соберёте цикл «мысль → действие», в котором модель решает, когда
позвать инструмент, а код выполняет вызов и возвращает результат.

После занятия ваш ассистент на вопрос «который час» не выдумывает время,
а сам вызывает вашу функцию и отвечает по её результату.

========================================================================
ШАГ 1. ЗАЧЕМ МОДЕЛИ ИНСТРУМЕНТЫ
========================================================================

Языковая модель предсказывает текст. На вопрос «который час?» у неё нет
часов — она достраивает правдоподобное продолжение. Иногда угадывает,
иногда нет, и по её тону этого не видно: одинаково уверенно звучат
и «14:32», и «9:47».

То же с любыми точными данными: сумма на счёте, список задач,
содержимое файла. Модель не «читает данные» — она сочиняет похожий на
ответ текст.

Понять это помогает бытовой пример. Представьте: вы в другой комнате,
а вас по телефону просят сказать, который час. Вы не угадываете число
по памяти — вы подходите к часам, смотрите на них и только потом
называете время. Часы — источник правды, а вы решаете, когда на них
посмотреть.

С моделью то же самое. Настоящий ассистент не просит модель «вспомнить
время», а даёт ей функцию, которая время реально смотрит. Модель сама
решает, когда эту функцию позвать, — как вы решаете подойти к часам.

ИНСТРУМЕНТ — это обычная функция Python, которую вы разрешаете модели
вызывать. Модель решает, КОГДА её позвать, а работу (посмотреть время,
сложить числа) выполняет ваш код, не модель.

ЗАПОМНИТЕ: числа и факты берутся из инструментов, а не выдумываются.
Модель в этой паре — диспетчер, а не исполнитель.

========================================================================
ШАГ 2. КАК УСТРОЕН FUNCTION CALLING
========================================================================

Function calling (вызов функций) — договор между вами и моделью из трёх
шагов, которые повторяются:

  1. ВЫ ОТПРАВЛЯЕТЕ. Вместе с сообщениями передаёте модели список
     инструментов — их имена, описания и параметры.
  2. МОДЕЛЬ РЕШАЕТ. Если нужен инструмент, она возвращает НЕ текст,
     а поле tool_calls: имя функции и аргументы в JSON. Например
     «вызови current_time без аргументов».
  3. КОД ВЫПОЛНЯЕТ. Вы читаете tool_calls, запускаете функцию и отдаёте
     результат обратно модели сообщением с ролью «tool». Модель пишет
     ответ уже на его основе.

Ключевая мысль: модель не выполняет функцию, а только называет, что
вызвать и с какими аргументами. Выполнение — всегда ваш Python-код.

========================================================================
ШАГ 3. JSON-СХЕМА ИНСТРУМЕНТА
========================================================================

Чтобы модель знала про инструмент, его описывают словарём — схемой.
Схему удобно собирать по частям: сначала имя, затем описание, в конце
параметры. Разберём каждую часть отдельно.

ПЕРВАЯ ЧАСТЬ — name. Это имя функции в вашем Python-коде. Модель
вернёт именно его, когда решит позвать инструмент, и ваш код по этому
имени найдёт нужную функцию:

    {
        "type": "function",
        "function": {
            "name": "current_time"
        }
    }

name обязано совпадать с именем функции в tools.py. Если в схеме
написано current_time, а функция называется cur_time, модель попросит
одно, а код найдёт другое.

ВТОРАЯ ЧАСТЬ — description. Это описание того, что инструмент делает.
Модель читает его как инструкцию и по нему решает, звать ли инструмент.
Пишите точно: не «посчитать», а «считает выражение из чисел и + - * /»:

    {
        "type": "function",
        "function": {
            "name": "current_time",
            "description": "Текущее время на компьютере в формате ЧЧ:ММ."
        }
    }

ТРЕТЬЯ ЧАСТЬ — parameters. Это описание аргументов инструмента. У
current_time аргументов нет, поэтому внутри пусто: properties = {}
и required = []. Собираем схему целиком — три части вместе:

    {
        "type": "function",
        "function": {
            "name": "current_time",
            "description": "Текущее время на компьютере в формате ЧЧ:ММ.",
            "parameters": {
                "type": "object",
                "properties": {},
                "required": []
            }
        }
    }

Параметр описывается в properties: {"expression": {"type": "string",
"description": "..."}}, а его имя попадает в required. Типы параметров:
"string", "integer", "number", "boolean". Полная шпаргалка — в файле
files/07_instrumenty/spravka_schema.txt.

========================================================================
ШАГ 4. ЦИКЛ «МЫСЛЬ → ДЕЙСТВИЕ → НАБЛЮДЕНИЕ»
========================================================================

Одного вызова может не хватить: модель позовёт инструмент, получит
результат и захочет позвать ещё один. Поэтому вызовы собирают в цикл.
Каждый виток — простая последовательность из трёх шагов:

  ШАГ 1. МЫСЛЬ. Модель решает, что делать, и либо отвечает текстом,
         либо просит вызвать инструмент.
  ШАГ 2. ДЕЙСТВИЕ. Ваш код читает просьбу модели и выполняет
         названную функцию.
  ШАГ 3. НАБЛЮДЕНИЕ. Результат функции возвращается модели сообщением
         с ролью «tool» — и цикл начинается заново, с шага 1.

Цикл повторяется, пока на шаге 1 модель не вернёт обычный текст. Чтобы
ассистент не застрял навсегда, цикл ограничивают: у вас не больше 8
итераций, иначе возвращаете фразу «Не удалось получить ответ». Сообщения
роли «tool» несут поле tool_call_id — по нему модель связывает ответ
функции с тем вызовом, который сама сделала.

========================================================================
ШАГ 5. ПРАВИЛА РАЗДЕЛЕНИЯ ОБЯЗАННОСТЕЙ
========================================================================

  1. Инструмент делает одно точное действие: вернуть время, сложить
     числа. Ничего лишнего.
  2. Модель решает, КОГДА вызвать. Вы не пишете «если вопрос про время,
     то вызови» — модель сама смотрит на описания и решает.
  3. Числа берутся из инструментов, а не сочиняются.
  4. Инструмент просто возвращает результат и ни о чём не спрашивает.

ОСТОРОЖНО: не давайте модели инструменты, которые пишут в файлы, шлют
письма или тратят деньги, пока не научились проверять их вызов. На этом
занятии — только безопасные функции: время и вычисления.

    # ЗАЧЕМ: модель просит вызов по имени, а выполняет его только код.
    # ПОЧЕМУ json: аргументы приходят строкой, их нужно распарсить.

    def dispatch(name, args):

ЗАДАНИЕ 3. СОБРАТЬ DISPATCH И ЦИКЛ В AGENT.PY
========================================================================

Добавьте в tools.py функцию dispatch, которая по имени зовёт нужный
инструмент:

    # ЧТО: по имени инструмента dispatch запускает нужную функцию.
    # ЗАЧЕМ: модель просит вызов по имени, а выполняет его только код.
    def dispatch(name, args):
        if name == "current_time":
            return current_time()
        # Запасной вариант: несуществующий инструмент — честный ответ, а не падение.
        return "Инструмент не найден: " + name

Создайте файл agent.py с циклом «мысль → действие». Системный промпт
возьмите из занятия 5 (Ася, помощник Алексея) — ниже он короткий:

    # json — парсит аргументы вызова; llm — клиент к модели;
    # ALL_TOOLS и dispatch — инструмент и его запуск из tools.py.
    import json
    import llm
    from tools import ALL_TOOLS, dispatch

    # ЧТО: характер Аси. ЗАЧЕМ: модель должна знать, кто она и как отвечать.
    # ПОЧЕМУ в коде: промпт один для всех вопросов, его не вводят каждый раз.
    SYSTEM_PROMPT = (
        "Ты Ася, личный помощник Алексея. Отвечай по-русски, "
        "коротко и по делу. Если нужны точные данные, "
        "вызывай инструмент и отвечай по его результату."
    )

    # ЧТО: цикл «мысль → действие». ЗАЧЕМ: одного вызова может не хватить.
    def run(user_msg):
        # Начало диалога: системный промпт плюс вопрос пользователя.
        messages = [
            {"role": "system", "content": SYSTEM_PROMPT},
            {"role": "user", "content": user_msg},
        ]
        # ПОЧЕМУ 8 шагов: чтобы модель не зациклилась на вызовах навсегда.
        for _ in range(8):
            msg = llm.chat(messages, tools=ALL_TOOLS)
            # Нет tool_calls — модель ответила текстом, он и возвращается.
            if not msg.get("tool_calls"):
                return msg.get("content") or ""
            # Модель попросила инструмент: её сообщение сохраняется в историю.
            messages.append(msg)
            for tc in msg["tool_calls"]:
                name = tc["function"]["name"]
                # ПОЧЕМУ or "{}": пустая строка аргументов не сломает json.loads.
                args = json.loads(tc["function"].get("arguments") or "{}")
                # Функцию выполняет код — модель её только называет.
                result = dispatch(name, args)
                # Результат возвращается модели ролью tool, чтобы ответ был по факту.
                messages.append({
                    "role": "tool",
                    "tool_call_id": tc.get("id", ""),
                    "content": result,
                })
        # ЗАЧЕМ: за 8 шагов не вышло — честный ответ вместо зависания.
        return "Не удалось получить ответ."

Запустите и спросите «Который час?»: оберните run() в input-цикл, как
на занятии 4, или вызовите print(run("Который час?")) прямо в файле.

СДЕЛАНО, ЕСЛИ: ассистент сам вызвал current_time и ответил временем,
совпадающим с часами компьютера, а не выдуманным. Это поля таблицы 7
«ассистент вызвал инструмент сам» и «результат вызова».

ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК
========================================================================

ПРОБЛЕМА: модель не возвращает tool_calls, а сразу пишет текст

Чаще всего две причины: схема кривая (name не совпадает с функцией,
description непонятный) либо модель/провайдер не поддерживает function
calling. Проверьте схему по spravka_schema.txt и убедитесь, что модель
из занятия 4 умеет инструменты. Вопрос «Который час?» почти всегда
требует инструмент — по нему и проверяйте.

ПРОБЛЕМА: KeyError: 'tool_calls'

Вы обращаетесь к полю tool_calls напрямую, а у ответа без инструмента
его нет. Проверяйте наличие через msg.get("tool_calls") — вернёт None,
если ключа нет, и код не упадёт.

ПРОБЛЕМА: аргументы не парсятся, ошибка json.loads

Модель может вернуть пустую строку в arguments. json.loads("") падает.
Лечится одной строкой: json.loads(tc["function"].get("arguments") or "{}")
— пустую строку заменяем на "{}", то есть «без аргументов».

ПРОБЛЕМА: ассистент зациклился и повторяет вызовы

Цикл не ограничен или лимит слишком большой. Поставьте for _ in range(8):
— за 8 шагов модель либо ответит, либо вернётся фраза «Не удалось
получить ответ».

ПРОБЛЕМА: ModuleNotFoundError: No module named 'requests'

Библиотека requests не установлена. Установите её, как на занятии 4:

    pip install requests

json и time ставить не нужно — они входят в Python.
