========================================================================
ШАГ 1. ОТКУДА БЕРУТСЯ ДАННЫЕ
========================================================================

Банк отдаёт историю операций в разных видах. Один присылает PDF, другой —
Excel (XLSX), третий — простой текст (CSV или TXT). Внутри у всех одно
и то же: список операций с датой, суммой и описанием, — но выглядит
каждый файл по-своему.

Ассистенту нельзя держать сто разных правил «как читать этот конкретный
файл». Поэтому первая задача — нормализация: превратить любой формат
в один и тот же вид. Наш единый вид — словарь из трёх полей:

    {"date": "01.09.2026", "amount": 120000.0, "description": "Зарплата, зачисление"}

date — дата строкой, amount — сумма числом, description — описание строкой.
Одна операция = один такой словарь. Дальше что ни делай — сводку, график,
вопрос «сколько ушло на еду» — всё работает с одинаковыми записями.

На курсе мы берём самый простой исходный формат — TXT, где поля разделены
символом «;». Парсеры для PDF и XLSX устроены сложнее, но идея та же:
вытащить строки и превратить их в такие словари.

========================================================================
ШАГ 2. УСТРОЙСТВО НАШЕЙ УЧЕБНОЙ ВЫПИСКИ
========================================================================

Откройте файл vypiska.txt. Сверху — шапка из четырёх строк:

    Банк А
    Выписка по счёту 40817********1234 за 01.09.2026 - 30.09.2026
    Клиент: Алексей И.
    Валюта: RUB

Это служебная информация: название банка, номер счёта, клиент, валюта.
Для реестра она не нужна, поэтому шапку надо пропустить.

Дальше идёт строка-заголовок «Дата;Сумма;Описание», а после неё — сами
операции. Каждая строка данных — три части, разделённые символом «;»:

    Дата;Сумма;Описание
    01.09.2026;+120 000,00;Зарплата, зачисление
    02.09.2026;-12 500,00;Аренда квартиры

Суммы записаны в «банковском» виде, а не в питоновском:

  * «+» в начале — приход (деньги пришли), «-» — расход (ушли);
  * пробел отделяет тысячи: 120 000;
  * запятая — десятичный разделитель: 284,50, а не 284.50.

Python такой текст числом не считает: float("+120 000,00") упадёт
с ошибкой. Поэтому первой и нужна функция, которая превращает такую
строку в обычное число.

========================================================================
ШАГ 3. parse_amount — НОРМАЛИЗАЦИЯ СУММЫ
========================================================================

Файл amounts.py содержит одну функцию parse_amount. Она берёт строку
вроде «-1 284,50» и возвращает число -1284.5:

    import re

    def parse_amount(s):
        if not s: return 0.0
        s = s.strip()
        sign = 1
        if s.startswith("+"): sign = 1; s = s[1:]
        elif s.startswith("-"): sign = -1; s = s[1:]
        s = s.replace(" ", "").replace("\u00a0", "")
        s = s.replace(".", "").replace(",", ".")
        return sign * float(s)

Разберём построчно:

  * if not s — пустую строку считаем нулём;
  * strip() — убирает лишние пробелы по краям строки;
  * sign — запоминаем знак, а сам «+» или «-» отрезаем;
  * replace(" ", "") — убираем обычные пробелы, а replace("\u00a0", "")
    — неразрывные пробелы, которые иногда подставляют программы;
  * replace(".", "") — убираем точки-разделители тысяч (бывает запись
    «1.284,50»); replace(",", ".") — меняем запятую на точку, как
    требует Python;
  * в конце — sign * float(s): число умножаем на запомненный знак.

Обратите внимание: порядок важен. Сначала убрали точки, потом заменили
запятую. Если перепутать местами, «1.284,50» превратится в «1.284.50»,
и float упадёт. Строка import re подключает модуль регулярных выражений:
он пригодится в занятии 9 для поиска слов в описаниях, а здесь
импортирован заранее.

========================================================================
ШАГ 4. ПАРСЕР: ПРОПУСТИТЬ ШАПКУ И РАЗБИТЬ СТРОКИ
========================================================================

Парсер — это функция, которая читает файл и возвращает список словарей.
Она лежит в файле parsers/txt.py:

    from amounts import parse_amount

    def parse_all(path):
        rows = []
        in_data = False
        with open(path, "r", encoding="utf-8") as f:
            for line in f:
                line = line.strip()
                if not line:
                    continue
                if not in_data:
                    if "Дата;Сумма" in line:
                        in_data = True
                    continue
                date, amount, description = line.split(";", 2)
                rows.append({
                    "date": date,
                    "amount": parse_amount(amount),
                    "description": description,
                })
        return rows

Ключевая мысль — флаг in_data («мы уже дошли до данных?»). Пока его
значение False, мы читаем шапку и ищем строку с «Дата;Сумма»; как только
нашли — переключаем флаг и дальше разбираем каждую строку как операцию.

Строку режет split(";", 2). Число 2 означает: делить максимум на три
части. Зачем? Если в описании попадётся свой «;», обычный split(";")
порвал бы строку на четыре куска и сломал разбор, а split(";", 2)
оставляет весь «хвост» в третьей части — описании.

Дату оставляем строкой как есть: для реестра «01.09.2026» — уже готовое
значение, превращать её в объект даты сегодня не нужно. Сумму прогоняем
через parse_amount, чтобы в базе лежало именно число.

========================================================================
ШАГ 5. РЕЕСТР: SQLite-ТАБЛИЦА transactions
========================================================================

Реестр — это таблица в базе данных. С SQLite вы уже работали на занятии 6,
когда учили ассистента запоминать факты. Сегодня добавляем таблицу
transactions: одна строка таблицы = одна операция. Файл db.py:

    import sqlite3

    def create_table(con):
        con.execute("""
            CREATE TABLE IF NOT EXISTS transactions (
                id INTEGER PRIMARY KEY AUTOINCREMENT,
                date TEXT,
                amount REAL,
                description TEXT
            )
        """)

    def insert_transactions(con, rows):
        con.executemany(
            "INSERT INTO transactions (date, amount, description) VALUES (?, ?, ?)",
            [(r["date"], r["amount"], r["description"]) for r in rows],
        )
        con.commit()

Колонки: id (номер, база присваивает сама), date, amount, description.
Строка CREATE TABLE IF NOT EXISTS — «создай таблицу, если её ещё нет»:
можно запускать скрипт много раз, и база не сломается.

Запись делает executemany. В отличие от execute, который пишет одну строку,
executemany принимает список и записывает его целиком — быстро и одним
куском. Знаки «?» — это плейсхолдеры: на их место база сама подставляет
значения, и мы защищены от проблем с кавычками в описаниях.

ОСТОРОЖНО: реальная выписка содержит персональные данные — имя, счёт,
названия магазинов, суммы. В учёбе мы работаем только с вымышленными
данными Алексея и «Банка А». Код, который обрабатывает настоящие деньги,
держите локально на своём компьютере и не вставляйте такие данные в чат
с моделью: модель — это внешний сервис, и ей ваша выписка не нужна.

ПРОБЛЕМА: дата и сумма перепутаны

В таблице transactions колонки идут date, amount, description — в том же
порядке, что и в INSERT, и в списке кортежей. Если переставить местами,
в колонке date окажется сумма и наоборот. Сверьте порядок трёх полей
во всех трёх местах.

ПРОБЛЕМА: no such table: transactions

Таблица не создана. Проверьте, что перед insert_transactions вызывается
create_table(con), а соединение con открыто к тому же файлу assistant.db.

ПРОБЛЕМА: UnicodeDecodeError при чтении файла

Файл читается не в той кодировке. В open() обязательно указывайте
encoding="utf-8":

    open(path, "r", encoding="utf-8")

ПРОБЛЕМА: расход выглядит как «145314.70000000002»

Это не ошибка, а особенность чисел с плавающей точкой. Для вывода
оборачивайте сумму в round(..., 2), как в демо 4. В самой базе число
остаётся точным настолько, насколько это нужно для сводок.
