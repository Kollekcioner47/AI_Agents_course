# Занятие 11. Каналы: Telegram-бот и веб-чат.

До этого занятия Ася жила в терминале: вы писали вопрос в консоли и там
же читали ответ. Это удобно, пока вы сидите за компьютером с открытым
редактором. Но личный помощник нужен как раз тогда, когда редактора под
рукой нет: с телефона по дороге, из браузера, с другого устройства.

Сегодня ассистент выходит из консоли к вам. Мы прикрутим к нему канал —
тонкий слой, который принимает сообщение из мессенджера или веб-страницы,
передаёт его уже готовому супервизору из занятия 10 и возвращает ответ
обратно. Сам ассистент не меняется: агенты Фёдор и Вера, память
и инструменты остаются теми же.

## ЧТО МЫ СДЕЛАЕМ

Выберем один из двух каналов — Telegram-бота или веб-чат — и подключим
его к готовому ассистенту. Разберём, чем каналы отличаются и как выбрать
нужный, напишем обработчик, который вызывает orchestrator.handle, и
закроем доступ от посторонних: только владелец сможет писать ассистенту.

После занятия Ася ответит вам не в консоли, а в Telegram или на
веб-странице — и откажет всем, кто не прошёл проверку доступа.

## ЧАСТЬ 1. ТЕОРИЯ: КАК АССИСТЕНТ ВЫХОДИТ К ПОЛЬЗОВАТЕЛЮ

### ШАГ 1. ЗАЧЕМ КАНАЛ, ЕСЛИ ЕСТЬ КОНСОЛЬ

Консоль хороша для разработки: видно ошибки, легко отлаживать. Для
пользования она неудобна по трём причинам:

  * ассистент работает, только пока запущена программа и открыт
  терминал — закрыли окно, и помощник замолчал;
  * писать можно только с того компьютера, где лежит проект;
  * каждый запуск — это отдельная команда, а не привычный чат.

КАНАЛ — это способ доставить сообщение от вас к ассистенту и ответ
обратно. Это пятый блок из занятия 1. Канал не добавляет ассистенту ума:
он только меняет «дверь», через которую вы входите. Внутри — тот же
оркестратор, те же агенты, та же память.

ЗАПОМНИТЕ: консоль после этого занятия никуда не девается. Она остаётся
вашим инструментом отладки, а канал — способом пользоваться ассистентом
каждый день.

### ШАГ 2. ДВА ВАРИАНТА И КАК ВЫБРАТЬ

У нас два готовых варианта, и они решают одну задачу по-разному:

  * TELEGRAM-БОТ (библиотека aiogram 3). Ассистент становится ботом
  в мессенджере. Плюсы: пишете с телефона, приходят уведомления,
  интерфейс знаком. Минусы: нужен токен бота (регистрация через
  BotFather), библиотека aiogram, доступ к серверам Telegram.

  * ВЕБ-ЧАТ (FastAPI + uvicorn). Ассистент отвечает на вашей странице
  в браузере. Плюсы: проще всего, токен не нужен, работает в локальной
  сети, полный контроль над страницей. Минусы: нет push-уведомлений,
  страница живёт, пока запущен сервер.

Как выбрать: хотите писать ассистенту с телефона и получать уведомления —
берите Telegram. Хотите просто и без токена, чтобы попробовать за десять
минут, — берите веб. На занятии рекомендуем веб: он проще, не требует
токена бота, а всё, что вы на нём поймёте, переносится на Telegram один
в один.

### ШАГ 3. ОДИН ВЫЗОВ HANDLE

Канал — это тонкая обёртка. Он ничего не знает про агентов, не заглядывает
в память и не вызывает модель сам. Его работа из трёх шагов:

  1. ПРИНЯТЬ текст сообщения;
  2. ВЫЗВАТЬ orchestrator.handle(con, message);
  3. ОТПРАВИТЬ ответ обратно.

Вся логика — маршрутизация между Фёдором и Верой, память, инструменты —
осталась в orchestrator из занятия 10. Канал её не дублирует, а только
доносит вопрос и ответ. Поэтому подключение канала — это один вызов
функции, которую вы уже написали.

Веб-канал в самом коротком виде:

```python
from fastapi import FastAPI
from pydantic import BaseModel
import orchestrator

app = FastAPI()

class ChatRequest(BaseModel):
    message: str

@app.post("/api/chat")
def chat(req: ChatRequest):
    answer, intent = orchestrator.handle(con, req.message)
    return {"answer": answer, "intent": intent}
```

Telegram-канал делает то же самое:

```python
from aiogram import Bot, Dispatcher, types
from aiogram.filters import CommandStart
import orchestrator

bot = Bot(token=TELEGRAM_BOT_TOKEN)
dp = Dispatcher()

@dp.message(CommandStart())
async def on_start(message: types.Message):
    await message.answer("Привет! Я твой ассистент.")

@dp.message()
async def on_message(message: types.Message):
    answer, intent = orchestrator.handle(con, message.text or "")
    if len(answer) > 4000:
        answer = answer[:4000] + "…"
    await message.answer(answer)
```

В обоих случаях один и тот же вызов handle. Отличие только в том, откуда
пришло сообщение и куда вернуть ответ.

ОСТОРОЖНО: TELEGRAM_BOT_TOKEN в коде — только имя переменной. Значение
токена лежит в .env и в файл с кодом не вписывается.

### ШАГ 4. ОГРАНИЧЕНИЕ ДОСТУПА: ТОЛЬКО ВЛАДЕЛЕЦ

Личный ассистент знает про вас то, что не должен знать никто другой.
Поэтому канал обязан отвечать только владельцу. Иначе любой, кто найдёт
адрес вашего сервера или имя бота, сможет задавать вопросы и читать ваши
данные.

Как это делается:

  * TELEGRAM — сверяем отправителя с владельцем из .env: ключи
  OWNER_TELEGRAM_ID (числовой id аккаунта) и OWNER_TELEGRAM_USERNAME
  (имя без @). Проверяем message.from_user.id и message.from_user.username.

  * ВЕБ — используем пароль: страница отправляет его вместе с сообщением,
  а сервер сверяет с WEB_PASSWORD из .env. Неверный пароль — отказ.

Проверка доступа стоит ПЕРЕД вызовом handle: чужой запрос не должен
дойти до ассистента вообще. Без этой проверки канал открыт всем, кто
дотянется до него.

### ШАГ 5. ЧТО ВАЖНО ПРИ ЗАПУСКЕ

Три вещи, которые ловят новичков:

  1. ASYNC. aiogram и FastAPI — асинхронные библиотеки. Обработчики
  пишутся со словами async/await, а Telegram-бот запускается через
  asyncio.run(main()). Если забыли async — библиотека сразу скажет
  об этом в ошибке.

  2. POLLING ПРОТИВ WEBHOOK. Два способа, как бот узнаёт о сообщениях.
  Polling — бот сам ходит в Telegram и спрашивает «есть новое?»:
  просто, ничего настраивать не надо, идеально для одного человека.
  Webhook — Telegram сам стучится на ваш сервер по адресу: нужен
  публичный адрес и HTTPS, это уже продакшен. На курсе используем
  только polling.

  3. ПОРТ И ПРОЦЕСС. Веб-чат слушает порт, например 8081. Если порт
  занят — меняем на другой. И помните: пока uvicorn или бот запущены,
  ассистент отвечает; нажали Ctrl+C — канал замолчал. Это нормально,
  надёжным автозапуском займёмся на занятии 12.

## ЧАСТЬ 2. ДЕМОНСТРАЦИЯ

Эту часть проводит преподаватель на своём экране. Ваша задача — смотреть

### ДЕМО 1. МИНИМАЛЬНЫЙ ВЕБ-КАНАЛ

Преподаватель создаёт файл web.py рядом с orchestrator.py:

```python
from fastapi import FastAPI
from pydantic import BaseModel

import orchestrator

app = FastAPI()

class ChatRequest(BaseModel):
    message: str

@app.post("/api/chat")
def chat(req: ChatRequest):
    answer, intent = orchestrator.handle(con, req.message)
    return {"answer": answer, "intent": intent}
```

Разбор по строкам:

  * app = FastAPI() — создаём приложение;
  * class ChatRequest(BaseModel) — описываем формат входящего запроса:
  поле message со строкой. FastAPI сам разберёт JSON и откажет, если
  поле не пришло;
  * @app.post("/api/chat") — этот обработчик вызывается на POST-запрос
  по адресу /api/chat;
  * orchestrator.handle(con, req.message) — тот самый один вызов;
  * return {"answer": ..., "intent": ...} — FastAPI превращает словарь
  в JSON-ответ.

ВЫВОД: канал — это 12 строк вокруг одного вызова handle.

### ДЕМО 2. СТРАНИЦА index_web.html

Обработчик /api/chat отвечает на запросы, но человеку нужна страница.
Добавляем в web.py обработчик главной страницы:

```python
from pathlib import Path
from fastapi.responses import HTMLResponse

@app.get("/", response_class=HTMLResponse)
def index():
    return Path("index_web.html").read_text(encoding="utf-8")
```

Преподаватель открывает files/11_kanaly/index_web.html и показывает

```python

    method: "POST",
    headers: { "Content-Type": "application/json" },

```

ВЫВОД: страница — это витрина, а вся работа происходит в /api/chat.
Страница посылает fetch-запрос, получает JSON и печатает поле answer.

### ДЕМО 3. ОГРАНИЧЕНИЕ ДОСТУПА ПАРОЛЕМ

Без пароля канал ответит любому. Добавляем пароль из .env и проверку.
В .env появляется строка:

```python
WEB_PASSWORD=мой_секретный_пароль
```

А в web.py — проверка ПЕРЕД вызовом handle:

```python
from config import WEB_PASSWORD

class ChatRequest(BaseModel):
    message: str
    password: str = ""

@app.post("/api/chat")
def chat(req: ChatRequest):
    if req.password != WEB_PASSWORD:
        return {"answer": "Доступ закрыт: неверный пароль.", "intent": ""}
    answer, intent = orchestrator.handle(con, req.message)
    return {"answer": answer, "intent": intent}
```

ВЫВОД: пароль сверяется до того, как сообщение дойдёт до ассистента.
Неверный пароль — отказ, оркестратор даже не вызывается.

```python
import asyncio

from aiogram import Bot, Dispatcher, types
from aiogram.filters import CommandStart

import orchestrator
from config import TELEGRAM_BOT_TOKEN, OWNER_TELEGRAM_ID, OWNER_TELEGRAM_USERNAME

bot = Bot(token=TELEGRAM_BOT_TOKEN)
dp = Dispatcher()

@dp.message(CommandStart())
async def on_start(message: types.Message):
    await message.answer("Привет! Я твой ассистент.")

def is_owner(message: types.Message) -> bool:
    uid = str(message.from_user.id)
    if OWNER_TELEGRAM_ID and uid == OWNER_TELEGRAM_ID:
        return True
    if OWNER_TELEGRAM_USERNAME and message.from_user.username == OWNER_TELEGRAM_USERNAME:
        return True
    return False

@dp.message()
async def on_message(message: types.Message):
    if not is_owner(message):
        await message.answer("Извините, я отвечаю только своему владельцу.")
        return
    answer, intent = orchestrator.handle(con, message.text or "")
    if len(answer) > 4000:
        answer = answer[:4000] + "…"
    await message.answer(answer)

async def main():
    await dp.start_polling(bot)

if __name__ == "__main__":
    asyncio.run(main())
```

В .env добавьте TELEGRAM_BOT_TOKEN и хотя бы один ключ владельца:
OWNER_TELEGRAM_ID или OWNER_TELEGRAM_USERNAME. Запустите:

## ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК

### ПРОБЛЕМА: порт занят, ошибка «address already in use»

```python

```

И откройте страницу по новому адресу http://127.0.0.1:8082.

### ПРОБЛЕМА: бот не отвечает на сообщения

Почти всегда — токен. Проверьте в .env строку TELEGRAM_BOT_TOKEN= :
она не пустая, без кавычек и лишних пробелов, а значение взято у
BotFather, а не из примера. Ещё причина: вы не нажали /start в чате
с ботом — Telegram не доставляет обычные сообщения, пока не стартовали.

### ПРОБЛЕМА: ошибка asyncio при запуске бота («Event loop is closed» и т.п.)

Polling запускают через asyncio.run(main()), а не вызывая main() напрямую
и не внутри уже работающего цикла. Убедитесь, что обработчики объявлены
с async, а в конце файла стоит блок if __name__ == "__main__" с
asyncio.run(main()).

### ПРОБЛЕМА: канал отвечает всем, доступ не ограничен

Вы не добавили проверку владельца/пароль. В вебе — сверка req.password
с WEB_PASSWORD из .env; в Telegram — проверка message.from_user.id или
message.from_user.username по OWNER_TELEGRAM_ID / OWNER_TELEGRAM_USERNAME.
Проверка должна стоять до вызова orchestrator.handle.
