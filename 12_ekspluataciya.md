## ЧАСТЬ 1. ТЕОРИЯ: КАК АССИСТЕНТ ВЫХОДИТ В РАБОТУ

### ШАГ 1. СЕКРЕТЫ: ФАЙЛ .ENV И ПОЧЕМУ НЕ В КОДЕ

Секрет — строка, которая даёт доступ: API-ключ модели, токен бота,
пароль от веб-чата. Кто владеет секретом, действует от вашего имени,
поэтому секрет хранят отдельно от кода.

Секрет нельзя писать в коде: код показывают, копируют, пересылают,
кладут в git. Как только ключ попал в файл, который ушёл кому-то или
в репозиторий, — считайте, что он утёк, и пересоздавайте. Один
неосторожный скриншот — и ключ уже не секрет.

Место для секретов — файл .env из строк вида «КЛЮЧ=ЗНАЧЕНИЕ»:

```python
NEURALDEEP_API_KEY=sk-ваш-ключ
TELEGRAM_BOT_TOKEN=123456:токен
```

.env лежит в папке проекта, но НЕ попадает в git: его имя вносят
в .gitignore — список того, что git не забирает:

```python
.env
backups/
__pycache__/
```

Образец — файл .env.example с ПУСТЫМИ значениями. Его можно показывать
и класть в репозиторий. Порядок такой: копируете .env.example в .env
и заполняете только свои значения. .env — секрет, .env.example — нет.

ОСТОРОЖНО: в реальном проекте «Личный помощник» пароль веб-чата имел
значение по умолчанию. Здесь вы этого не делаете: пароль и ключи
задаются ТОЛЬКО через .env, без значений по умолчанию в коде. Пароль,
зашитый в код по умолчанию, — это пароль, который все уже знают.

### ШАГ 2. БЭКАПЫ: ЧТО ХРАНИТЬ И СКОЛЬКО ВЕРСИЙ

Бэкап — архив, из которого ассистента можно восстановить, если диск
умер, файл удалили или код что-то испортил. Бэкапить надо два вида
вещей:

  * ДАННЫЕ — папку data: базу памяти, заметки, распознанные выписки;
  * НАСТРОЙКИ И СЕКРЕТЫ — файл .env: без него ассистент не подключится
  к модели и каналу.

Одной копии мало: если она единственная и битая, всё пропало. Поэтому
хранят несколько последних версий. Правило — 7 штук: хватит откатиться
на неделю назад, и папка не разрастётся. Имя архива несёт дату:

```python
backup_20250115_093000.zip
```

ОСТОРОЖНО: бэкап, в который попал .env, — такой же секрет, как сам
ключ. Храните его в своей папке, не в публичном облаке, не пересылайте.

### ШАГ 3. РАСПИСАНИЕ: ЗАЧЕМ АССИСТЕНТУ РЕГУЛЯРНЫЕ ЗАДАЧИ

Ассистент полезен, когда работает без вас. Для этого нужны регулярные
задачи, выполняемые сами по времени:

  * ЕЖЕДНЕВНАЯ СВОДКА — утром ассистент готовит сводку и пишет в канал;
  * САМОПРОВЕРКА — раз в день проверить, что бот жив, модель отвечает
  и данные на месте.

Планировщик — бесконечный цикл: выполнить задачу, посчитать, сколько
осталось до следующего запуска, и уснуть на это время через time.sleep.

На сервере вместо цикла используют cron или systemd — системные
механизмы, переживающие перезагрузку. Для учебного ассистента хватит
простого цикла: он наглядно показывает «запуск по расписанию».

### ШАГ 4. БЕЗОПАСНОСТЬ КАНАЛОВ: ТОЛЬКО ВЛАДЕЛЕЦ

На занятии 11 ассистент вышел в Telegram и веб. Сегодня закрепляем
правило, без которого канал — открытая дверь: отвечать только владельцу.

  * TELEGRAM: ассистент принимает сообщения только от OWNER_TELEGRAM_ID
  и молча игнорирует остальных;
  * ВЕБ: вход по логину и паролю (WEB_LOGIN и WEB_PASSWORD) — оба только
  из .env;
  * БУДУЩАЯ ПОЧТА: белый список ALLOWED_SENDERS — адреса, которым
  разрешено писать. Всё остальное отбрасывается.

Белый список — «разрешить перечисленным, запретить остальным». Он
надёжнее чёрного: вы не угадаете все плохие адреса, но знаете свои
хорошие.

### ПРИМЕР 1. ЗАПОЛНЕННЫЙ .ENV И config.py

Заполненный .env выглядит так. Все значения — заглушки:

```python
LLM_PROVIDER=neuraldeep
NEURALDEEP_API_KEY=sk-ЗАГЛУШКА
NEURALDEEP_BASE_URL=https://api.neuraldeep.ru/v1
NEURALDEEP_MODEL=qwen3.8-27b
TELEGRAM_BOT_TOKEN=123456:ЗАГЛУШКА
OWNER_TELEGRAM_ID=ЗАГЛУШКА
WEB_LOGIN=alexey
WEB_PASSWORD=ЗАГЛУШКА
BACKUP_DIR=backups
BACKUP_KEEP=7
ALLOWED_SENDERS=
```

config.py читает эти строки. Главное правило: у несекретных настроек
есть значения по умолчанию, а у секретов — нет:

```python
# Стандартная библиотека: os читает переменные окружения,
# pathlib.Path удобно работает с путями к файлам и папкам.
import os
from pathlib import Path

def load_env(path=".env"):
    # Читаем .env один раз при импорте, чтобы значения
    # попали в os.environ и стали доступны остальному коду.
    env = Path(path)
    if not env.exists():
        return
    for line in env.read_text(encoding="utf-8").splitlines():
        line = line.strip()
        # Пропускаем пустые строки и комментарии: это не настройки.
        if not line or line.startswith("#") or "=" not in line:
            continue
        # Делим по первому "=", чтобы значение могло само
        # содержать "=" (например, в токене Telegram).
        key, value = line.split("=", 1)
        # setdefault: переменная окружения важнее .env, поэтому
        # уже заданное значение не перезаписываем.
        os.environ.setdefault(key.strip(), value.strip().strip('"').strip("'"))

load_env()

# Не секреты: адреса и имена моделей безопасно показывать,
# поэтому у них есть значения по умолчанию.
LLM_PROVIDER = os.environ.get("LLM_PROVIDER", "neuraldeep")
NEURALDEEP_BASE_URL = os.environ.get("NEURALDEEP_BASE_URL", "https://api.neuraldeep.ru/v1")
NEURALDEEP_MODEL = os.environ.get("NEURALDEEP_MODEL", "qwen3.8-27b")
OLLAMA_BASE_URL = os.environ.get("OLLAMA_BASE_URL", "http://127.0.0.1:11434/v1")
OLLAMA_MODEL = os.environ.get("OLLAMA_MODEL", "qwen3:8b")

# Секреты: значение по умолчанию НЕ задаём. Без .env они равны
# None, и ассистент не запустится «на пароле по умолчанию».
NEURALDEEP_API_KEY = os.environ.get("NEURALDEEP_API_KEY")
TELEGRAM_BOT_TOKEN = os.environ.get("TELEGRAM_BOT_TOKEN")
OWNER_TELEGRAM_ID = os.environ.get("OWNER_TELEGRAM_ID")
WEB_LOGIN = os.environ.get("WEB_LOGIN")
WEB_PASSWORD = os.environ.get("WEB_PASSWORD")

# Пути и число хранимых бэкапов — настройки с разумными
# значениями по умолчанию, это не секреты.
DATA_DIR = Path(os.environ.get("DATA_DIR", "data"))
BACKUP_DIR = Path(os.environ.get("BACKUP_DIR", "backups"))
BACKUP_KEEP = int(os.environ.get("BACKUP_KEEP", "7"))

# Список адресов из .env через запятую; пустые куски отбрасываем.
ALLOWED_SENDERS = [s.strip() for s in os.environ.get("ALLOWED_SENDERS", "").split(",") if s.strip()]
```

ВЫВОД: config.py не хранит секреты — он их читает. Значение по умолчанию
есть только у того, что можно показывать. Без .env пароль и ключ равны
None, и ассистент честно не запускается, а не работает «на пароле
по умолчанию».

### ПРИМЕР 2. БЭКАП И ОЧИСТКА СТАРЫХ

Создайте backup.py:

```python
# zipfile создаёт архив, time подставляет дату в имя файла,
# pathlib обходит папки, config даёт пути и число копий.
import zipfile
import time
import pathlib
import config

def create_backup():
    # Папку бэкапов создаём заранее, чтобы первая копия не упала.
    config.BACKUP_DIR.mkdir(exist_ok=True)
    # В имя кладём дату и время: по нему видно, какая копия свежая.
    name = time.strftime("backup_%Y%m%d_%H%M%S.zip")
    target = config.BACKUP_DIR / name
    # ZIP_DEFLATED сжимает архив, чтобы он занимал меньше места.
    with zipfile.ZipFile(target, "w", zipfile.ZIP_DEFLATED) as zf:
        # В архив кладём папку data целиком — это накопленные данные.
        if config.DATA_DIR.exists():
            for f in sorted(config.DATA_DIR.rglob("*")):
                if f.is_file():
                    zf.write(f, f.relative_to(config.DATA_DIR.parent))
        # Файл .env кладём отдельно: без него новый ассистент
        # не подключится к модели и каналу.
        env = pathlib.Path(".env")
        if env.exists():
            zf.write(env, env.name)
    print("Создан бэкап:", target)
    return target

def prune_old(keep=None):
    # Сколько копий хранить: по умолчанию берём из config.py.
    keep = keep if keep is not None else config.BACKUP_KEEP
    # Сортируем архивы по имени — дата в имени даёт порядок
    # от старого к новому.
    backups = sorted(config.BACKUP_DIR.glob("backup_*.zip"))
    # Удаляем всё, что не вошло в последние keep копий.
    for old in backups[:-keep]:
        old.unlink()
        print("Удалён старый бэкап:", old.name)
    return backups[-keep:]

if __name__ == "__main__":
    # При запуске файла напрямую создаём копию и чистим старые.
    create_backup()
    prune_old()
```

Запустите:

```python
python backup.py
```

На экране:

```python
Создан бэкап: backups/backup_20250115_093000.zip
```

Откройте архив и проверьте, что внутри папка data и файл .env. Запустите
backup.py несколько раз, чтобы накопилось больше семи архивов, — после
каждого запуска prune_old удалит лишние:

```python
Создан бэкап: backups/backup_20250115_100000.zip
Удалён старый бэкап: backup_20250108_090000.zip
```

ВЫВОД: бэкап — это папка data плюс .env в одном zip с датой. Старых
копий никогда не больше семи: лишние удаляются сами.

### ПРИМЕР 3. ПЛАНИРОВЩИК

Создайте scheduler.py с одной ежедневной задачей и циклом, который спит
до следующего запуска:

```python
# time замеряет время и усыпляет программу между запусками задачи.
import time

def daily_task():
    # Пока это заглушка: печатаем время и строку, что ассистент жив.
    # Позже сюда подставите настоящую сводку или самопроверку.
    print(time.strftime("%H:%M:%S"), "— сводка за день: ассистент жив.")

def run_scheduler(interval_seconds, task):
    # Бесконечный цикл: выполняем задачу, затем спим до следующего раза.
    while True:
        # Запоминаем начало, чтобы вычесть время работы задачи
        # из интервала — запуски не съезжают из-за самого запуска.
        started = time.time()
        task()
        elapsed = time.time() - started
        # max(0, ...) не даёт уснуть на отрицательное время,
        # если задача выполнялась дольше интервала.
        sleep_for = max(0, interval_seconds - elapsed)
        print("Следующий запуск через", int(sleep_for), "секунд.")
        time.sleep(sleep_for)

if __name__ == "__main__":
    # Сутки = 86 400 секунд. Для проверки поставьте 60.
    run_scheduler(60, daily_task)
```

Чтобы не ждать сутки, интервал для проверки поставьте 60 секунд. Запуск:

```python
python scheduler.py
```

На экране раз в минуту появляется строка задачи:

```python
09:30:00 — сводка за день: ассистент жив.
Следующий запуск через 60 секунд.
```

Остановка — Ctrl+C. ВЫВОД: планировщик — бесконечный цикл с time.sleep.
На сервере его заменит cron или systemd, но смысл тот же: задача
выполняется сама по времени.

## ЕСЛИ ЧТО-ТО ПОШЛО НЕ ТАК

### ПРОБЛЕМА: ключ не читается, config.py возвращает None

Проверьте две вещи: имя переменной в .env и в config.py совпадают
побуквенно (регистр важен: NEURALDEEP_API_KEY — не neuraldeep_api_key),
и в строке .env нет лишних пробелов и кавычек. Строка «KEY = "значение"»
не равна «KEY=значение». Проще всего убрать всё лишнее и оставить
«КЛЮЧ=значение» без пробелов.

### ПРОБЛЕМА: бэкап создался, но внутри пусто

Значит, путь к папке data неверный. config.py по умолчанию берёт DATA_DIR
из «data», то есть папка data должна лежать в корне проекта рядом
с backup.py. Проверьте, что она называется именно data и что в .env
строка DATA_DIR не указывает на несуществующее место. Откройте архив
и посмотрите, что реально попало внутрь.

### ПРОБЛЕМА: архивов становится всё больше, старые не удаляются

prune_old не вызывается или keep слишком большой. Убедитесь, что в конце
запуска идёт prune_old(), а в config.py BACKUP_KEEP равен 7. Проверьте,
что имена архивов начинаются с backup_ — иначе prune_old их не найдёт
и не удалит.

### ПРОБЛЕМА: планировщик зациклился и не отпускает терминал

Это не ошибка, а его работа: бесконечный цикл. Остановите клавишами
Ctrl+C — программа прервётся и терминал вернётся. Если интервал случайно
поставили огромным, просто нажмите Ctrl+C, поправьте число и запустите
снова.

### ПРОБЛЕМА: .env случайно попал в git/репозиторий

Добавьте строку .env в файл .gitignore и зафиксируйте изменение. Но этого
мало: если ключ уже успел уйти в историю, он скомпрометирован. Удалите
его из истории, а надёжнее всего — пересоздайте ключ у провайдера
и положите новый в .env. Утёкший ключ не «отзывается» простым удалением
файла.
